01 Project — Jarvis (Multi-Agent AI Assistant)

Problem: A normal chatbot forgets everything and can't take actions. I wanted an assistant that remembers me and can act safely on my behalf.
Solution: A manager–worker system — one FastAPI orchestrator + ~90 specialist agents, a two-layer memory, and a 4-tier safety model, on the Claude Agent SDK.

The /chat pipeline (the core flowchart)

1 · Intent
Haiku classifies: 8 categories + priority
∥ parallel
2 · Recall
ChromaDB semantic search, score ≥ 0.55
↓  augmented = intent + memory + msg
3 · Worker
run_worker() — Claude Agent SDK
Spawns a Claude session in the Jarvis dir (sees all agents/tools). Streams answer, captures session_id + cost.
↓
4 · Critic
silent Haiku reviewer — 4 rubrics
Intent · Memory · Claims · Tone → verdict revise = one rewrite. Fails open (never blocks the reply).

Memory = RAG over my own history

Two layers: (1) structured Markdown files (facts/preferences/projects); (2) a vector DB — every conversation embedded with all-MiniLM-L6-v2 into ChromaDB, retrieved by cosine similarity, trimmed to a token budget. Auto-capture cron ingests new facts every 30 min.

✓ Used & why

  • Manager–worker + asyncio parallel — fan-out N workers, each own context.
  • Haiku for intent/critic — cheap + fast for classification.
  • Score-threshold recall (0.55) — kills irrelevant-memory noise.
  • Separate critic model — self-correction without self-approval bias.
  • 4-tier safety — irreversible actions need human approval.

✗ Rejected & why

  • Single mega-prompt agent — no auditability, weaker per-domain.
  • No-memory chatbot — forgets context every turn.
  • Inject all recalled chunks — noise → confident-wrong answers.
  • Same-model self-critique — approval bias; use a separate reviewer.
  • Full-auto everything — unsafe for send/delete/publish.
Interview line: "Jarvis is a manager–worker agentic system with RAG memory and a separate-model self-correction loop — the same pattern I used for the Tata maintenance copilot."

02 Tata Steel Round 1 — Defect Prediction (Tabular ML)

Problem: Binary classification — predict the "Alpha defect" per steel coil in a Hot Rolling Mill from 49 anonymized sensor features. 1352 × 51 train 4.88% defect rate only 66 positives

Scoring formula (yaad rakho): Score = (Recall + Precision) / 2 × 100. Missed defect (recall) costs way more than a false alarm → recall-leaning threshold. The exact set of flagged rows is what's optimized, not a probability ranking.

Final approach — 5-paradigm consensus (flowchart)

Base
V4 stack — the load-bearing baseline
LightGBM + XGBoost + CatBoost → Logistic-Regression meta + Platt calibration. Features: SHAP-selected + polynomial + coil-neighbor temporal (defect auto-correlates coil-to-coil, 5.28× lift). Stratified 5-fold, fold-isolated FE.
↓ feeds into
V35
per-stand deviations · 9-model avg
V39
CoilID schedule feats
V40
defect-proximity
V41
sequence feats
V43
rank-product AND-gate
↓ vote + rank-percentile consensus
Output
Top K=200 flagged → Y=1  ·  V44 = 72.83 LB → V71 = 74.72 LB
Non-parametric consensus (vote count + rank tiebreak) — adds no learnable weights to overfit the tiny 66-positive set.

Class imbalance — the key ML decision

Only ~13 positives per fold. Handled with cost-weighting, not resampling: scale_pos_weight ≈ 19.48 for LGB/XGB, class_weight=balanced for sklearn learners.

✓ Used & why

  • GBM trio (LGB/XGB/CatBoost) — best on pure tabular sensor data, no encoding.
  • Stratified 5-fold + fold-isolated FE — no leakage on 66 positives.
  • Cost-weighting (scale_pos_weight) — imbalance without fake data.
  • Non-parametric consensus (vote/rank) — beat stacking, zero overfit.
  • Platt calibration + threshold sweep on (R+P)/2.

✗ Tried & rejected (with the LB damage)

  • Probability blending → −8 to −35 LB. Averaging shifts the flagged-row set for a set-based metric.
  • Abstain-cascade post-hoc rule (V27) → CV said +1, LB −34.89. OOF-tuned rules break under prevalence shift.
  • Weak Stage-2 cascade (V58) → −16 LB. Stage-2 must be ≥ Stage-1 in CV-AUC.
  • SMOTE — interpolates noise in 49-D → false positives.
  • TabPFN / FT-Transformer / deep tabular — too few rows, no gain.
  • Anomaly detection (IsoForest/OCSVM/LOF) — defects are "stealth", invisible in features.
Best story (say this): "My honest ML ceiling was 74.72, and I proved it's structural — reaching LB 80 needs AUC ≥ 0.95 but the anonymized features cap at ~0.89, because ~7 defects are statistically invisible. The 100-scores on the board were leaderboard-probing, not a generalizing model — and I'm transparent about that difference." → shows ML maturity.

03 Tata Steel Round 2 — EDITH (Agentic Maintenance Copilot)

Problem: Build an agentic "Maintenance Wizard" for a steel plant — diagnose faults, find root cause (RCA), predict remaining useful life (RUL), prioritize actions, and give explainable, traceable recommendations. Individual build, 10 days. Tata gave no dataset, so I built a physics-grounded synthetic one (~1.25M rows, 120 run-to-failure episodes, 15 assets).

Architecture (three-tier flowchart)

Frontend
Next.js 16 + React 19 cockpit
Dark-HUD control room: 15-asset health strip, uPlot 60fps live charts, alerts feed, "Ask EDITH" copilot, PDF report. REST + SSE.
↓
Backend
FastAPI (SSE streaming)
/stream historian replay · /focus fast verdict (no LLM) · /ask full reasoning · /predict /report /feedback
↓
VULCAN engine
Custom Supervisor (router) → static agent DAG
intent → Diagnosis → Predictor → RCA → Recommender → Prioritizer
Every agent is deterministic — runs ML + RAG + ground-truth lookups. No agent calls an LLM.
↓ agents build a numbered [N] evidence block
The ONE LLM call
Claude synthesis → NLI faithfulness gate
Claude writes prose only from numbered facts. Then a separate DeBERTa NLI model checks each cited claim entails its source → verified/unverified/low badge.

Shared services

RAG
bge-small embed → FlashRank rerank → ChromaDB → NLI gate
ML
LightGBM fault (3-class) + LightGBM RUL + IsolationForest anomaly
LLM ladder
demo-cache → Claude OAuth → Ollama SLM → template floor

✓ Used & why

  • Multi-agent router DAG — inspectable reasoning trace = explainability (FR4); scores on "agentic frameworks".
  • Deterministic agents, 1 synthesis call — fast, auditable, hallucination-resistant.
  • Separate NLI (DeBERTa) faithfulness gate — grounds every maintenance claim; avoids self-approval bias.
  • LightGBM + IsolationForest — beats deep learning on PdM, CPU-friendly, explainable.
  • Local RAG (bge-small + FlashRank + ChromaDB) — keyless, CPU, free.
  • Proactive auto-diagnosis on first ALARM — the "agentic" proof: acts with zero input.

✗ Rejected & why

  • LangGraph — framework overhead on a solo CPU build; dynamic LLM routing risks hallucinated nodes. Static DAG is deterministic.
  • Single "chat-with-PDF" call — auto-lose anti-pattern, no agentic credit.
  • Deep learning RUL (LSTM/Transformer) — slower, no accuracy gain vs GBM on this data.
  • API embeddings (OpenAI/Cohere) — need a key + cost; violated keyless constraint.
  • Fine-tuned SLM as live brain — 4–8 tok/s CPU too slow; shipped as FR1 evidence + optional rung only.
  • Same-model self-critique — replaced by external NLI verifier.
Agentic patterns to name: router/intent-dispatch · tool-using grounded agents (ReAct-style but deterministic) · single grounded-synthesis + external-verifier reflection · human-in-the-loop feedback · proactive autonomous triggering · multi-turn stateful memory.

07 Golden Rules (interview jeetne ka)

1. Har fundamental ko project se jodo. "What is a decision tree?" → theory (Gini/split) + "...and I used gradient-boosted trees, LightGBM & CatBoost, in my Tata Round 1 defect model."

2. Numbers bolo. "Round 2", "rank 22", "74.72 honest ceiling", "1.25M-row dataset", "~90 agents", "0.55 threshold".

3. "Kyun nahi X?" ka jawab hamesha ready. Section 05 ki table ratlo — used vs ignored + reason.

4. Honesty = strength. R1 mein "100 was probing, my real model is 74.72" bolna maturity dikhata hai, kamzori nahi.

5. Follow-up invite karo. Har answer ke end pe interviewer ko deeper jaane ka mauka do — confidence dikhta hai.
