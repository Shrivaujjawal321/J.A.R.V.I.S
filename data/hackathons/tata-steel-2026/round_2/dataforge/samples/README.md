# DataForge Sample Datasets — Steel Plant Historian Export

Physics-based synthetic sensor datasets simulating a hot-strip-mill conveyor roller drive
with an attached motor. Generated by `make_steel_samples.py`.

---

## Files

### 1. `steel_good_runtofailure.csv` — Clean Multi-Asset Run-to-Failure
**43,550 rows | 14 columns | 15 assets | 0% missing**

Purpose: Primary demo + seed dataset. Scores HIGH on DataForge.

What it contains:
- 60 healthy runs (300–900 cycles each) across 15 asset IDs
- 12 fault runs (350–1100 cycles each) with 4 fault modes: outer_race, inner_race, rolling_element, lubrication
- Class distribution: HEALTHY 94.2%, WARNING 2.4%, ALARM 2.3%, FAILURE 1.2%
- Failure rate (ALARM+FAILURE combined): 3.5% — realistic industrial imbalance
- Zero missing values, zero timestamp duplicates, zero label noise

Physics grounding:
- Weibull degradation ramp (shape k=2.0–5.0 per fault type, ISO 281 / Jardine 2006)
- 6x6 Cholesky-correlated noise (temp_bearing ↔ vibration 0.68, temp_motor ↔ current 0.72)
- BPFO/BPFI bearing fault envelope modulation injected into vibration channel
- ISO 10816-3 zone boundaries respected: healthy 2.5 mm/s → alarm 9-12 mm/s → failure 12-15 mm/s
- RUL anchored at degradation_index > 0.85 (same threshold as FAILURE label, ISO 13381-1)
- Label smearing at boundaries (±25 cycle window, 20% flip rate) prevents trivially separable decision surface

Schema (historian-compatible, OSIsoft PI / AVEVA style):

| Column | Type | Description |
|--------|------|-------------|
| timestamp | datetime | UTC, 1 Hz historian rate |
| asset_id | str | Equipment ID (EQP-001 to EQP-015) |
| equipment_class | str | Asset class (roller_bearing, conveyor_drive, etc.) |
| temperature_bearing_c | float32 | Bearing housing temp (°C) |
| temperature_motor_c | float32 | Motor winding temp (°C) |
| vibration_mm_s | float32 | Radial vibration RMS (mm/s) |
| pressure_bar | float32 | Hydraulic clamping pressure (bar) |
| rpm | float32 | Roller shaft speed (RPM) |
| current_a | float32 | Motor phase current (A) |
| fault_type | str | healthy / outer_race / inner_race / rolling_element / lubrication |
| fault_label | int8 | 0=HEALTHY, 1=WARNING, 2=ALARM, 3=FAILURE |
| rul_cycles | int32 | Remaining useful life (cycles to FAILURE threshold) |
| severity | str | human-readable: healthy / warning / alarm / failure |
| sequence_id | str | Run/episode UUID prefix (8 chars) |

### 2. `steel_weak_dirty.csv` — Same Physics + Injected Defects
**35,515 rows | 14 columns | 10 assets | 9.2% missing**

Purpose: "Before" state in the DataForge improve-loop demo. Scores LOWER than the good dataset.

Same physics base (Weibull degradation, Cholesky-correlated noise) as the good dataset,
then six defect types injected as a post-processing pass:

| Defect Type | What Was Injected | Expected DataForge Flag |
|-------------|-------------------|------------------------|
| Point dropouts | ~7-9% NaN per sensor column | Missing value rate |
| Missing chunks | 2-4 blackout episodes (10-90 cycle NaN runs per sensor) | Consecutive gap detection |
| Sensor drift | 1-2 sensors with capped linear bias (+25% max of baseline) | Range / distribution shift |
| Timestamp duplicates | ~1.5% of rows have exact-duplicate timestamps | Duplicate timestamp detection |
| Flat-line freeze | 1-2 freeze episodes (8-50 cycles stuck at constant value) | Zero-variance detection |
| Mislabels | ~2.2% of fault_label values flipped ±1 class | Label noise / inconsistency check |

DataForge scoring expectation: ~10-20 points lower than the good dataset.

## Physics Simplifications (Honest)

1. **1 Hz sampling**: True bearing fault frequencies (BPFO ~18.5 Hz at 300 RPM) are above Nyquist. The vibration channel contains the RMS-power envelope modulation (what a 1-Hz historian actually stores), not the raw spectral sidebands. Real BPFO spectral analysis requires 25+ kHz acquisition.

2. **Correlation magnitude diluted in bulk dataset**: In the full ~43K row dataset, cross-sensor correlations are diluted by 94% healthy rows (all sensors near baseline). In degrading episodes, the designed correlations (temp_bearing ↔ vibration: 0.68+) are much clearer.

3. **Multi-asset label smearing**: The 20% label-flip at label boundaries creates a small fraction of FAILURE-labelled rows outside the degradation tail (high RUL). This mirrors real annotation uncertainty where a human labeller reviewing paper records has ±25-cycle timing uncertainty. It prevents trivially separable decision boundaries but means the check "all FAILURE rows have RUL<80" fails by design.

4. **Weibull parameters**: Shape k=2.0–5.0 and onset_fraction values are within the ISO 281/Jardine 2006 published ranges for rolling-element bearings. The exact scale parameter for a specific OEM bearing at a specific mill would require real plant data.

5. **Pressure and RPM cross-correlations**: The designed hydraulic-compensation correlation (pressure ↔ RPM: −0.30) appears weaker (−0.1) in the bulk dataset because the healthy baseline variation dominates. The correlation is correctly encoded in the Cholesky noise structure and is visible when conditioning on fault episodes only.
